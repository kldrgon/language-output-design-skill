# 句内信息结构

本文件分三块：语序、名称、谓语。完整案例见 [../examples/information-structure/clause-structure.md](../examples/information-structure/clause-structure.md)。

## 语序

判断和条目谁在前，看两件事：上文有没有把这个判断立成当前议题，以及第一次出现时要把注意和记忆锚在哪一侧。不要为了全篇整齐规定一种语序。

- 上文已经在问、或已经立住这个判断：可以列举事项，判断可以留在后句。不必再改写成“判断 + 是 + 列举”。
- 上文还没有这个判断：第一次出现的成分会拿到更多注意，并成为后续记忆节点。先提名，读者从名称锚定，主要记住事物本身，状态是次要的。先报状态或判断，读者从状态锚定，事项挂在这个状态下面。
- 这一节要让人先抓住“还没定”“已通过”时，判断放在第一次出现的位置。这一节要让人先认出有哪些对象时，名称放在第一次出现的位置。
- 换序的条件是当前注意中心和这一次要留下的锚点，不是固定格式。

首次出现的成分是理解的地基，不是“越前越重要”。Gernsbacher 的 Structure Building 里，先提到的参与者会铺成后续映射的基础，因而更容易被再次取用。Halliday 把句首称作 Theme，即话语的出发角度；新闻性往往仍在句尾的 New。汉语里句首常做话题，Li 与 Thompson 称为 topic-prominent：先立框架，再评述。句首 ERP 研究也显示，汉语句首位置主要由话题性引导加工。

因此先提名是把对象设成地基，先报状态是把状态设成地基。不要把句首写成唯一重点，也不要把英语的主语罗列加句尾判断当成默认。详细边界见 [../foundations/research-basis.md](../foundations/research-basis.md)。

## 名称

同一对象在同一篇里只保留一个名称。

- 书面定名之后，解释机制时继续用这个名字。
- 口语可以用更短的说法，但同一段口播或问答里仍然只留一个。
- 书面名和口语名不要在同一篇里混用。读者会当成两个对象或两种状态。

## 谓语

状态变化要落在谓语上，让读者直接读出挡住、开始、结束、等待这些关系。

- 一个谓语能说清时，写出关系本身。
- 需要保留因果时，把条件写进“因……而……”。
- 不要用需要二次翻译的隐喻串代替关系。时间、方式和结果可以同时出现在谓语里，只要关系是显式的。
