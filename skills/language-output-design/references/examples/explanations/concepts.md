# 概念解释案例

## 定义代替机制

**场景**  
向初学者解释数据库事务。读者已经知道数据库可以保存数据，但不理解为什么需要事务。

**原文**

> 事务是数据库中的逻辑工作单元，具有原子性。

**问题**  
这句话给出了术语和属性，但没有说明事务解决什么状态问题。读者无法判断“原子性”与实际操作的关系。

**改写**

> 转账需要同时减少一个账户的余额并增加另一个账户的余额。事务把这两个修改作为整体处理，全部成功时一起提交，中途失败时一起撤销。原子性描述的就是这种“全部完成或全部不发生”的关系。

**改写依据**  
从半完成状态的风险进入，再把具体关系映射到术语。读者先理解问题，再理解概念。

## 示例没有解释映射

**场景**  
在 API 文档中说明缓存控制参数。读者已经知道 HTTP 响应头，但不清楚 `max-age` 的具体作用。

**原文**

> 设置 `Cache-Control: max-age=3600`。

**问题**  
只给出结果，读者无法判断数字和机制的关系，也不知道这个设置会影响什么行为。

**改写**

> 设置 `Cache-Control: max-age=3600` 后，缓存可以在一小时内直接复用该响应。`3600` 表示响应保持新鲜的秒数，它决定缓存何时需要再次联系原始服务器。

**改写依据**  
说明参数、状态和后续行为之间的映射，使读者能够根据需求调整数值。

## 类比越界

**场景**  
向没有缓存概念的读者解释缓存的作用。读者可能把“仓库”理解为永久存储。

**原文**

> 缓存就是仓库。

**问题**  
类比范围不明，容易让人把缓存理解为永久存储，忽略缓存可能过期或失效。

**改写**

> 可以把缓存暂时理解成工作台，常用数据放得更近，取用更快。这个类比只说明访问距离和速度；缓存项可能过期，权威数据仍由原始存储维护。

**改写依据**  
指出有效映射和失效边界，防止读者把类比过度推广。

## 单例导致表面记忆

**场景**  
教学材料中解释“缓存”的通用结构。读者已经看过一个浏览器缓存的例子，但可能只记住表面形式。

**原文**

> 浏览器复用仍在新鲜期内的网页响应，减少网络请求。

**问题**  
只给一个案例，读者可能把“缓存”等同于“网页缓存”，无法迁移到其他场景。

**改写**

> 浏览器复用仍在新鲜期内的网页响应，减少网络请求。  
> 应用复用刚计算出的报表结果，减少重复计算。  
> 两个案例都暂存可重复使用的结果，并在有效条件不再成立时重新获取或计算。

**改写依据**  
第二个案例表面不同但结构相同，帮助读者从“网页缓存”中抽取通用关系。
