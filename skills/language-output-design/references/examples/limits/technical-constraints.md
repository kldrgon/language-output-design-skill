# 技术限制案例

## 版本兼容限制

**场景**  
在 API 文档中说明某个参数的使用限制。读者需要知道该参数在哪个版本引入，以及旧版本如何处理。

**原文**

> 使用 `filter` 参数过滤结果。

**问题**  
没有说明版本要求，旧版本用户可能尝试使用不存在的参数。

**改写**

> `filter` 参数在 v2.1 引入。v2.0 及更早版本请使用 `query` 参数，或升级到 v2.1 后使用 `filter`。

**改写依据**  
说明版本限制和替代方案，避免用户在旧版本上遇到错误。

## 权限边界

**场景**  
在管理后台文档中说明某个操作的权限要求。读者需要知道哪些角色可以执行该操作。

**原文**

> 管理员可以删除用户。

**问题**  
没有说明“管理员”具体指哪些角色，也没有说明权限不足时的表现。

**改写**

> 只有 `admin` 和 `super_admin` 角色可以删除用户。`moderator` 角色尝试删除时会收到 `403` 错误。删除操作会记录审计日志，包括执行者、目标用户和时间戳。

**改写依据**  
明确权限边界和审计行为，帮助读者理解操作的影响。

## 平台差异

**场景**  
在跨平台工具文档中说明文件路径的处理方式。读者需要知道不同操作系统的差异。

**原文**

> 使用 `/` 作为路径分隔符。

**问题**  
没有说明 Windows 使用 `\`，也没有说明工具是否自动处理差异。

**改写**

> 工具内部统一使用 `/` 作为路径分隔符。在 Windows 上，工具会自动将 `\` 转换为 `/`，因此配置文件中使用两种分隔符都可以。但在脚本中拼接路径时，建议使用 `/` 以确保跨平台兼容。

**改写依据**  
说明平台差异和工具行为，帮助读者避免兼容性问题。
