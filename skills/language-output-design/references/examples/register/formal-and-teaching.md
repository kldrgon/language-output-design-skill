# 正式说明与教学讲解案例

## 正式说明缺少责任

**场景**  
在变更通知中说明一项配置修改的影响。读者需要知道谁负责执行、何时执行、如何验证。

**原文**

> 配置已更新，请知悉。

**问题**  
没有说明责任人、执行时间、影响范围或验证方式，读者无法判断是否需要采取行动。

**改写**

> 运维团队已于 2026-08-28 14:00 更新生产环境的 `timeout` 配置，从 5000 毫秒调整为 10000 毫秒。此次修改影响所有 API 请求。请各团队在 24 小时内检查服务日志，确认无超时异常。如有问题，请联系运维团队。

**改写依据**  
明确责任、时间、影响和验证方式，使读者能够判断是否需要行动。

## 教学讲解缺少中间状态

**场景**  
向新手解释如何使用 Git 解决冲突。读者已经知道如何提交代码，但不知道冲突如何解决。

**原文**

> 运行 `git merge` 后解决冲突，然后提交。

**问题**  
没有说明冲突的表现、解决步骤或验证方式，新手无法独立完成任务。

**改写**

> 运行 `git merge` 后，如果两个分支修改了同一文件的同一部分，Git 会标记冲突。打开冲突文件，找到 `<<<<<<<`、`=======` 和 `>>>>>>>` 标记，选择保留哪部分或合并两部分。保存文件后，运行 `git add` 标记冲突已解决，再运行 `git commit` 完成合并。

**改写依据**  
提供关键中间状态和明确因果，使新手能够跟随步骤完成任务。

## 简短答复缺少必要条件

**场景**  
用户询问如何查看当前 Git 分支。用户已经熟悉命令行，只需要一条命令。

**原文**

> 使用 Git 命令查看分支。

**问题**  
没有给出具体命令，用户需要额外查找。

**改写**

> 运行 `git branch --show-current`。

**改写依据**  
简短答复直接给出可执行命令，不添加无关背景。

## 混合受众分层

**场景**  
在技术博客中解释缓存策略。读者包括新手和熟手，需要同时满足两类受众。

**原文**

> 缓存是一种提高性能的技术。缓存可以存储数据，以便快速访问。缓存有很多类型，例如内存缓存、分布式缓存和浏览器缓存。每种类型都有不同的用途和实现方式。

**问题**  
对新手来说，解释过于抽象；对熟手来说，信息过于基础。没有分层，两类读者都需要过滤冗余内容。

**改写**

> 缓存通过暂存可重复使用的结果，减少重复计算或网络请求。  
>   
> 对新手：可以把缓存理解成工作台，常用数据放得更近，取用更快。缓存项可能过期，权威数据仍由原始存储维护。  
>   
> 对熟手：当前实现使用本地缓存，负载因子达到 0.75 时扩容。远程缓存需要额外处理序列化和版本兼容。

**改写依据**  
先提供共同主线，再把基础解释和深入细节分层，避免所有层次挤进同一段。
