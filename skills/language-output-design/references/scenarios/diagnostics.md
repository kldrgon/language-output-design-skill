# 诊断说明

## 目标

通过证据逐步缩小原因范围，并给出能增加信息的下一步。

## 组织流程

先复述已知现象和范围，避免把用户的解释当作已证实事实。随后区分以下内容。

- 已观察事实
- 当前最可能的解释
- 其他仍合理的解释
- 每个解释需要什么证据验证

说明证据与判断之间的关系。不要只列原因清单；应解释为什么当前现象支持某个原因，以及什么结果会否定它。

验证步骤按信息增益和风险排序。优先执行低风险、能够明显区分假设的检查。获得新证据后更新判断，不重复原列表。

## 表达不确定性

应具体说明哪些事实已经确定，哪些原因尚未确定。

> 日志只证明连接在 10:32 被关闭，尚不能确定是服务端超时还是客户端主动断开。

不要只作空泛保留。

> 可能有很多原因，需要进一步分析。

## 验证

每个诊断动作都应回答一个明确问题。若动作无论得到什么结果都不会改变判断，就不应执行。
